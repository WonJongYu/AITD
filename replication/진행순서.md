# 길병원 폐쇄망 분석 실행 순서

## 전체 파이프라인

```text
DB 컴퓨터: 코호트 → AITD 라벨 → feature → QA → dataset.csv
    ↓ 승인 USB
Python 컴퓨터: 라이브러리 설치 → 전처리 → RFECV → 모델링
→ hold-out 평가 → SHAP·threshold·KM → Table/Figure·PDF
```

## 1. DB 컴퓨터: SQL 실행

### 1-1. 실행 폴더 생성

```bash
mkdir replication_sql_run_YYYYMMDD
cd replication_sql_run_YYYYMMDD
```

실행별 결과가 섞이지 않도록 새 폴더에서 시작한다.

### 1-2. CDM·Vocabulary schema 확인

- `cdm_schema`: `person`, `drug_exposure`, `measurement` 등 임상 테이블 위치
- `vocabulary_schema`: `concept`, `concept_ancestor` 등 vocabulary 테이블 위치

DB에 접속하여 실제 schema 이름을 확인한다.

```bash
psql -X -h HOST -p PORT -U USER -d DATABASE_NAME
```

```sql
SELECT table_schema, table_name
FROM information_schema.tables
WHERE lower(table_name) IN (
  'person', 'observation_period', 'drug_exposure',
  'condition_occurrence', 'measurement',
  'concept', 'concept_ancestor', 'concept_relationship'
)
ORDER BY table_schema, table_name;
```

예를 들어 임상 테이블이 `cdm`, vocabulary가 `vocabulary`에 있으면 아래 실행 명령에
다음과 같이 넣는다.

```text
-v cdm_schema=cdm
-v vocabulary_schema=vocabulary
```

모든 테이블이 같은 `cdm` schema에 있으면 두 값 모두 `cdm`으로 입력한다. 같은
테이블이 여러 schema에서 발견되면 임의로 선택하지 말고 DB 담당자에게 길병원 분석용
OMOP CDM schema를 확인한다. 확인 후 `\q`로 접속을 종료한다.

### 1-3. 전체 SQL 실행

```bash
set -o pipefail
psql -X -v ON_ERROR_STOP=1 \
  -h HOST -p PORT -U USER -d DATABASE_NAME \
  -v cdm_schema=실제_CDM_SCHEMA \
  -v vocabulary_schema=실제_VOCABULARY_SCHEMA \
  -f /승인된_경로/replication/run_all_replication_postgresql.sql \
  2>&1 | tee sql_execution.log
```

자동 실행 순서:

1. `cohort3_selection.sql`: 코호트 및 배제 기준
2. `labeling3.sql`: AITD 라벨과 관찰 종료점
3. `demographics3_extraction.sql`: 기술통계
4. `feature3_extraction.sql`: 약물·질환·검사 feature
5. `qa3_postgresql.sql`: 중복·누수·구간 오류 검사

### 1-4. 결과 확인

```bash
ls -lh dataset.csv cohort_flow_summary.csv replication_qa_summary.csv
wc -l dataset.csv
cat replication_qa_summary.csv
```

SQL 오류나 QA 이상이 있으면 다음 단계로 넘어가지 않는다.

## 2. Python 컴퓨터: 인터넷 연결 중 설치

먼저 `requirements-model.txt`만 복사하고 USB를 분리한 뒤 인터넷을 연결한다.

```bash
mkdir replication_python_run_YYYYMMDD
cd replication_python_run_YYYYMMDD

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r /승인된_경로/requirements-model.txt

python -m pip check
python -c "import pandas, sklearn, xgboost, imblearn, shap, lifelines, reportlab; print('Packages OK')"
python --version > python_environment.txt
python -m pip freeze >> python_environment.txt
```

필요한 라이브러리를 일괄 설치하고 실제 버전을 기록한다. 오류가 없으면 인터넷을
종료한다.

## 3. Python 컴퓨터: 인터넷 종료 후 자료 복사

복사 후 USB를 분리한다.

## 4. 모델링 실행

```bash
cd /승인된_경로/replication_python_run_YYYYMMDD
source .venv/bin/activate
export XGB_DEVICE=cpu
export MODEL_N_JOBS=1

set -o pipefail
jupyter nbconvert --to notebook --execute --inplace \
  --ExecutePreprocessor.timeout=-1 \
  'preprocessing&model.ipynb' \
  2>&1 | tee model_execution.log
```

GPU 사용이 확인된 경우에만 `XGB_DEVICE=cuda`로 변경한다.

노트북 처리 순서: 마지막 완전 관찰구간 선택 → development/hold-out 분리 → fold 내부
MICE·scaling → AdaBoost·XGBoost 5-fold RFECV → 두 모델 feature 교집합 → 16개
모델·sampling 조합 튜닝 → hold-out 평가 → SHAP·OOF threshold·KM 분석.

- RFECV 선택 기준: `accuracy`
- 하이퍼파라미터 기준: development 5-fold `macro-F1`
- hold-out test: 모든 선택이 끝난 뒤 한 번만 평가

## 5. 표·그림·보고서 생성

```bash

  --input-dir /승인된_경로/replication_python_run_YYYYMMDD \
  --template REPORT_TEMPLATE.md \
  2>&1 | tee report_generation.log
```

`report_outputs`에 Table 1–6, Figure 1–5, Markdown, HTML 및 PDF 보고서가 생성된다.

```bash
find report_outputs -maxdepth 2 -type f | sort
```

표본 수·단위·선택 feature·성능·그림을 확인한다. 환자 수준 CSV, 예측값과 SHAP 자료는
반출하지 않고 병원이 승인한 집계 결과만 전달한다.
